# 学习记录：递归停止条件总是写晚

学生：林晓雨  
课程：算法与数据结构入门  
本周目标：能独立写出递归函数的停止条件，再写递归调用。

我把最近两周做递归题的记录、OJ 导出的错题表、助教反馈页都放在这里，希望系统帮我判断下一步该怎么练。

## 手动记录

2026-04-20 周一  
看完了递归导论课。老师讲 `factorial` 和 `sum_list` 时我能跟着画调用栈，但自己写代码时会先想“下一层怎么调用”，很少先问“什么时候停”。课后只做了 1 道课堂例题，照着板书写出来了。

2026-04-24 周五  
在 LeetPractice 做了 5 道递归基础题，通过 2 道。  
- `factorial-variant`：失败。代码先写了 `return n * factorial(n - 1)`，忘记处理 `n == 0`。运行后出现 maximum recursion depth exceeded。  
- `count-down`：失败。希望打印 3, 2, 1，但 `n = 0` 时还继续调用 `count_down(-1)`。  
- `sum-list`：通过，但用了提示才想到空数组。  
- `tree-depth-basic`：失败。我只判断了叶子节点，没有处理空子节点。  
- `palindrome-recursion`：通过，这题我先写了长度小于等于 1 的情况，所以比较顺。

2026-04-26 周日  
复盘时发现自己常常把 base case 放在递归调用之后。错误不是语法，而是写函数前没有先列最小输入。尤其是 `n == 0` 和 `n == 1`，我会犹豫 factorial 应该停在哪里。

2026-04-30 周四  
助教批注：“递归结构接近正确，但停止条件缺失或出现太晚。建议每次先写最小输入和返回值，再写 recursive case。”
